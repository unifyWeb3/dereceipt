## 0. What I changed from the discovery draft, and why

Discovery recommended per-criterion LLM consensus with a published *agreement
margin*. **The margin is not obtainable. I was wrong.** GenLayer's own
documentation is explicit:

> The leader's result is only accepted if a majority of validators agree… The
> accepted leader result is the value your contract receives and can store.
> Validators verify or reject that leader result; **their independent
> intermediate answers are not automatically persisted on-chain.**
> — `docs.genlayer.com/developers/intelligent-contracts/equivalence-principle`

A contract **cannot** count how many validators agreed. Any plan that reports
that number is reporting something it does not have. This would have failed in
implementation, and it would have failed review.

The observable, on-chain truth about a jury is three things:

1. **Which criteria reached a verdict at all.** A criterion that ends
   `UNDETERMINED` is a criterion the jury visibly could not agree on. That is
   real, on-chain, and countable.
2. **Whether a challenge succeeded.** A challenge that is upheld is direct,
   priced evidence that the original verdict was wrong.
3. **The cumulative overturn rate.** Derived by reading storage, per program,
   forever.

So the wedge is rebuilt on those three. Everything below follows from this.

## 2. The product

### The one-sentence pitch

> Every AI-judged hackathon throws away its own jury's disagreement. This keeps
> it: for every criterion, a verdict against evidence frozen at submission with
> point-in-time proof it existed before the deadline; every case the jury could
> not agree on, kept on the record instead of discarded; every challenge and its
> outcome, permanent; and after five programs, an accuracy rate nobody else has.

### The customer

The organiser of a sponsor-funded hackathon or grant round who must publish a
result they can defend to a sponsor **and** to a runner-up who disagrees.
Primary buyer and primary user are the same person. The competitor entrant is
the *evidence source*, not the customer — do not design the UI around entrants.

## 3. What GenLayer decides, and what it must not

This split is inherited from the 360/400 build and is what earned it points.

### Deterministic, over authoritative data — no LLM, no dispute possible

All of this is decided by arithmetic over facts fetched from the GitHub API and
committed to chain. A fact is a fact; a model has no authority over it.

| Check | Source | Rejects when |
| --- | --- | --- |
| `repo_resolves` | `GET api.github.com/repos/{o}/{r}` | non-200 → `UNDETERMINED` (not a rejection) |
| `commit_resolves` | `GET api.github.com/repos/{o}/{r}/commits/{sha}` | 404 → disqualified; 403/429/5xx → `UNDETERMINED` |
| **`commit_predates_deadline`** | `commit.commit.committer.date` vs stored deadline | committer date ≥ deadline → **disqualified** |
| **`tree_digest`** freeze | `GET api.github.com/repos/{o}/{r}/git/trees/{sha}?recursive=1`, hashed | stores the digest of the file manifest |
| `not_duplicate` | stored `tree_digest` set in the program | digest already present → disqualified |
| `required_files_present` | frozen tree manifest | `README.md` absent → disqualified |
| `declared_language_present` | frozen tree manifest vs entrant's declared stack | entrant declares `typescript`, tree has no `.ts` → **claim refuted** |
| `demo_reachable` | `GET demo_url` on an allow-listed host | 404 → disqualified; other → `UNDETERMINED` |

`commit_predates_deadline` is the headline. It is a *point-in-time proof that
the work existed before the rules closed*, derived from a signed-by-GitHub
timestamp that no entrant can forge after the fact — and nobody on the platform
is doing it.

`declared_language_present` is the anti-self-description check. Entrants describe
their own work; nothing on the platform checks the description against the
artifact. Here, the frozen tree is the witness.

### Where consensus comes from — the lesson from 360/400

The 360/400 contract makes its decision with **zero LLM calls**. Verified by
grepping the saved source in `evidence/reference-360-build/`:

- `gl.nondet.web.get(...)` — fetch the authoritative source
- `validator_fn` **re-runs `leader_fn()` itself** and compares the normalized
  decision fields
- `gl.vm.run_nondet(leader_fn, validator_fn)`

So the intelligence is not a model. It is **independent re-derivation under
consensus**: no single operator and no off-chain server decides anything, and
every validator must independently reach the same verdict from the same
authoritative source. That is exactly the pattern the GenLayer docs prescribe
for objective facts, and it is what scored 360/400.

Read the rubric with that in mind: *"Solves a real trust problem. **Not just a
better LLM response.**"* A build with no LLM in the decision path satisfies that
clause in the most literal way available — and it removes the single largest
technical risk in the plan.

**Therefore: the LLM is optional and last.** §5 places it at M3.5, after the
whole product already works without it. If M1 fails, or you judge the reviewer
risk too high, **ship without it.** The product is complete and defensible with
zero LLM calls, and that is the shape that earned 360/400.

Two further consequences, both deliberate:

- **Every challenge ground except `UNSUPPORTED_CLAIM` is deterministic too.**
  `AFTER_DEADLINE_WORK` is `committer.date`; `DUPLICATE_SUBMISSION` is
  `tree_digest`; `DEAD_DEMO` is an HTTP status; `MISSING_REQUIRED_FILE` is the
  frozen manifest. So the dispute mechanism — the wedge — does not depend on the
  LLM existing at all.
- **`declared_language_present` covers most of `UNSUPPORTED_CLAIM`
  deterministically**, by checking the declared stack against the frozen tree. The
  LLM step, if present, only handles the residue: narrative claims in prose.

### Bounded LLM — optional, one criterion, no authority

If and only if M1 passes, `run_panel` answers **one** question about **one**
criterion the organiser marked `subjective` at open time: *does the submitted
repository's own README describe a working product consistent with the evidence
frozen at submission?*

- Returns a **2-bucket** decision: `CONSISTENT` / `INCONSISTENT`, plus a
  `confidence` decile.
- Consensus-critical field: the bucket, compared with **±0 tolerance** — bucket
  A vs bucket B is disagreement, full stop. No fuzzy band, because a fuzzy band
  hides exactly the disagreement this product exists to keep.
- Hard gate: missing or unreadable README → `INCONCLUSIVE`, no verdict. Silence
  is never evidence.
- Free-form reasoning is stored but **never compared**.
- The contract returns `UNDETERMINED` when the jury cannot agree, and writes
  nothing. That is the feature, not a bug: the criterion is now visibly
  contested.
- **It can never release funds, disqualify an entry, or trigger a refund.** Those
  stay deterministic. The most this step can do is label one criterion.

### The accuracy record

Per program, derived on read from storage — never from a counter that can drift:

```
entries                     total
disqualified_deterministically
contested_criteria          criteria that ended UNDETERMINED
challenges_filed
challenges_upheld
overturn_rate               upheld / filed, as basis points, integer
overturn_by_ground[ground]  upheld / filed per accusation ground
```

`get_receipt_digest` returns a Keccak over the canonical JSON of the program's
audit record, so an organiser can prove months later that the record they
published is the record the chain holds. `Keccak256` is already proven to
import in this SDK.

### 4.2 Studio-dev quirks, all measured by someone who already hit them

| Quirk | Consequence | Rule for this build |
| --- | --- | --- |
| Value transfers posted `on="finalized"` are **queued and never executed** | GrantJudge measured a 22.6 GEN real balance against 4.7 GEN of books. Message receipts showed `message_value_effects[*].skipped=true`. | Use the **`gl.evm.contract_interface` external-message path** for EOA transfers. | Fee **estimation** is wrong for any method that both reads the block clock and posts a transfer | The simulator runs on a clock ~664 days stale, simulates on the wrong side of the appeal window, and the tx reverts `out_of message_fee total`. | **Never combine a clock read and a transfer in one method.** The clock-reading callback marks state; a separate no-clock method moves value. |

| **Docker is unavailable** in this environment | Integration tests that need it cannot run. | Direct tests must not require Docker. Say so plainly in the docs rather than pretending. |
| Unauthenticated `api.github.com` is 60 req/h **per calling IP** | Validators run on other machines. A 403 must never become a rejection. | **403 / 429 / 5xx → `UNDETERMINED`**, never `FAIL`. Only a 404 is a business rejection. This exact rule is why the 360 build's checks were sound. |

**`submit_entry` and `freeze_entry` are deliberately separate.** Storing the
entry is cheap and cannot fail on the network. Capturing the evidence is
expensive, hits `api.github.com` unauthenticated, and can end `UNDETERMINED` on a

instead of stranding a paid stake.

| Method | Kind | Clock? | Moves value? |
| --- | --- | --- | --- |
| `open_program(name, criteria_json, deadline_secs, challenge_window_secs, flags_json)` | write.payable | yes | yes (locks pool) |
| `submit_entry(program_id, repo_url, commit_sha, demo_url, declared_stack, claims_json)` | write.payable | yes | yes (small stake) |
| `freeze_entry(program_id, entry_index)` | write | no | no |
| `challenge(program_id, entry_index, ground, evidence_url)` | write.payable | yes | yes (bond) |
| `finalize_program(program_id)` | write | yes | no |
| `claim_payout(program_id, entry_index)` | write | **no** | **yes** |
| `cancel_program(program_id)` | write | yes | yes (refund pool) |
| `_on_entry_finalized(...)` | write (callback) | yes | no |
| `get_program` · `get_entry` · `get_receipt` · `get_accuracy` · `get_receipt_digest` · `get_contract_balance` | view | no | no |

`run_panel` is **M3.5 only** — it is the optional bounded-LLM criterion and does
not exist in M3.

> The 360/400 reference has 9 public methods and **10 tests**. That ratio is
> most likely why 40 points were missing. 13 methods against a **45+** test
> target is roughly 3.5 tests per method, which is the point of this build.

Hard rules for the implementation:

1. **No `raise` statements in a method that received value.** A revert in a
   payable method strands that value. GrantJudge's rule 2, and it is correct.
2. **Criteria are snapshotted onto the program at `open_program`.** No setter,
   ever. No method may change a criterion, a deadline, or a weight after open.
3. **The original verdict is never overwritten.** A challenge outcome is
   recorded *beside* it. The receipt is append-only.
4. **`cancel_program` is restricted** to `OPEN` programs with no adjudicated
   entry, returns the full pool, and is idempotent-safe. This is the fix for
   gap 1 — it gets its own tests and its own live evidence.
5. **One challenge per entry.** Once. Inside the window. Only against a
   *standing* entry. A disqualified entry has nothing to contest.
6. **Every non-200 from GitHub is `UNDETERMINED`; only 404 is a rejection.**
7. **Storage is bounded.** Store the tree digest, counts, and a capped manifest
   summary — never rendered HTML. The 360 build capped responses at 200 KB;
   cap the stored manifest tighter and say what the cap is.
8. **The transfer method reads no clock.** The callback reads the clock and
   moves no value. §4.2.

**Gate:** `genvm-lint check` clean **and** the live `gen_getContractSchemaForCode`
probe over raw JSON-RPC both pass; the contract derives **≥9 methods** on the
live probe; no `raise` in any payable method; no clock read sharing a method with
a transfer. Note the gate is a *floor* of 9, not a target of 9 — the design is
13.

### M4 · Direct tests (5 h) — **this is where the 40 points were lost**

Target **45+ tests** (the 360 build had 10). Group them the way the 360 build's
`VERIFICATION.md` describes, because reviewers read that taxonomy:

| Group | Cover |
| --- | --- |
| Canonicalisation | repo URL forms, SHA case, `urlsplit`/`urlunsplit` round-trip |
| Malformed shapes | every length bound, empty strings, bad hosts, non-40-hex SHAs, injection attempts in every text field |
| Deadline boundary | exactly-at-deadline, one second either side, `committer.date` parsing |
| Duplicate | same `tree_digest` twice → second refused |
| Declared vs measured | declared `typescript` with no `.ts`; declared `python` with only `.js`; declared `rust` → refuted |
| Source failure | 403 / 429 / 500 / empty body / non-JSON → `UNDETERMINED`, **never** `FAIL` |
| Digest integrity | stored digest ≠ recomputed digest → refuse |
| Auth | only the entrant may submit their own; only the programme owner may finalise or cancel; only a non-winning standing entrant may challenge |
| Challenge | correct ground, wrong ground, expired window, second challenge refused, bond returned on `DENIED`, bond forfeited on `UPHELD` |
